# Тендер-бот

Telegram-бот, который следит за тендерными площадками и присылает новые тендеры,
подходящие под ключевые слова. Сайты и ключевые слова настраиваются прямо в боте —
код править не нужно.

## Что умеет

- **Админка внутри Telegram** — добавление сайтов, ключевых слов и админов через меню.
- **Автоподбор селекторов** — при добавлении сайта бот сам находит список тендеров
  на странице и показывает превью для подтверждения.
- **Ключевые слова с логикой** — точное слово, префикс (`ремонт*`), фраза целиком,
  минус-слова (`-аварийный`).
- **Без повторов** — каждая позиция уведомляется один раз (дедупликация по ссылке).
- **Без спама при подключении** — при добавлении сайта текущие тендеры помечаются
  просмотренными, приходят только новые.

## Быстрый старт локально

```bash
npm install
cp .env.example .env.local   # заполните значения
npm run bot:local
```

`npm run bot:local` запускает бота через long polling — публичный URL не нужен.
Сайты проверяются каждые `CHECK_INTERVAL_MINUTES` минут (по умолчанию 15).

Переменные окружения:

| Переменная | Где взять |
|---|---|
| `TELEGRAM_BOT_TOKEN` | [@BotFather](https://t.me/BotFather) → `/newbot` |
| `OWNER_TELEGRAM_ID` | [@userinfobot](https://t.me/userinfobot); можно несколько через запятую |
| `DATABASE_URL` | Neon Postgres (см. ниже) |
| `CRON_SECRET` | любая длинная случайная строка: `openssl rand -hex 32`. Только латиница и цифры — секрет уходит в заголовке запроса, а туда кириллица не помещается |
| `INGEST_SECRET` | ещё одна такая же строка — только для приёма страниц от домашнего сборщика; необязательна, без неё берётся `CRON_SECRET` |
| `BOT_URL` | адрес бота; нужен только на компьютере, где стоит сборщик |

## Деплой на Vercel

```bash
npx vercel link          # привязать проект
npx vercel env pull      # позже — забрать переменные локально
```

1. **База данных.** В дашборде проекта → *Storage* → *Marketplace* → **Neon Postgres**.
   После подключения `DATABASE_URL` появится в переменных проекта автоматически.
2. **Остальные переменные.** Добавьте `TELEGRAM_BOT_TOKEN`, `OWNER_TELEGRAM_ID`,
   `CRON_SECRET` для окружений Production и Preview:

   ```bash
   npx vercel env add TELEGRAM_BOT_TOKEN production
   ```
3. **Деплой.**

   ```bash
   npx vercel --prod
   ```
4. **Инициализация.** Один раз откройте в браузере:

   ```
   https://<ваш-домен>.vercel.app/api/setup?secret=<CRON_SECRET>
   ```

   Это создаст таблицы и подпишет бота на webhook. В ответ придёт `{"ok":true,...}`.

   Повторять этот шаг после деплоя с новыми таблицами или колонками не обязательно:
   если база отстала от кода, бот один раз докатывает схему сам и повторяет запрос
   (`withSchema` в `src/lib/db.ts`). Открыть `/api/setup` руками всё равно можно —
   миграция идемпотентна, а заодно она переподписывает webhook.
5. Напишите боту `/menu` в Telegram.

## Расписание проверок

`vercel.ts` содержит cron на `/api/cron`. **На Hobby-плане Vercel Cron срабатывает
только раз в сутки** — поэтому в конфиге стоит ежедневный запуск, иначе деплой не пройдёт.

Чтобы проверять чаще, есть два пути:

- **Pro-тариф** — поменяйте в `vercel.ts` расписание на `*/15 * * * *`.
- **Внешний планировщик** (бесплатно, работает и на Hobby) — например
  [cron-job.org](https://cron-job.org): создайте задание с интервалом 15 минут на адрес

  ```
  https://<ваш-домен>.vercel.app/api/cron?secret=<CRON_SECRET>
  ```

Кнопка «▶️ Проверить сейчас» в меню бота запускает обход вручную в любой момент.

## Площадки, которые пускают только с обычного компьютера

Некоторые сайты отвечают домашнему компьютеру и серверу по-разному. Живой пример —
`procurement.kg`. Откройте его в браузере дома — виден список тендеров. Тот же адрес
с сервера, где живёт бот, отдаёт страницу «Just a moment…»: сайт видит, что запрос
пришёл из дата-центра, и просит подтвердить, что за ним человек. Проверено: с сервера
приходит отказ, из дома — те же 32 тендера, что видит человек.

Поэтому есть **сборщик** — он работает на вашем компьютере. Каждые 15 минут сборщик
спрашивает у бота, какие страницы нужны, открывает их так же, как это делает браузер,
и отправляет боту. Дальше всё как обычно: поиск по ключевым словам, отсев уже
показанного и рассылка в Telegram остаются на стороне бота.

Что нужно, чтобы это работало: компьютер включён и в интернете. Пока он спит, сбор
пропускается и сам продолжается после пробуждения. Если ноутбук был выключен неделю —
эту неделю такие площадки не проверялись; остальные сайты бот всё это время проверял сам.

### Установка

Всего пять шагов. Каждый — это либо нажатие в Telegram, либо команда, которую
достаточно скопировать и вставить в приложение «Терминал».

**Шаг 1. Добавьте площадку в боте.** Без этого шага сборщику нечего качать:
он спросит бота, какие страницы нужны, получит пустой список и ничего не сделает.

В Telegram: откройте бота, напишите ему `/menu` и нажмите по очереди
**🌐 Сайты** → **⭐ Готовые площадки** →
**«Все тендеры Кыргызстана (procurement.kg)»** → **➕ Добавить**.
Бот ответит, что читать её будет с вашего компьютера.

**Шаг 2. Поставьте Node.js, если его ещё нет.** Это программа, без которой сбор
не запустится; ставится один раз. Скачайте установщик с [nodejs.org](https://nodejs.org)
(большая кнопка **LTS**) и запустите его. Проверить, что всё встало:

```bash
node -v
```

В ответ должно появиться что-то вроде `v22.14.0`. Если пишет
`command not found: node` — установщик не доработал: закройте окно Терминала,
откройте заново и повторите команду.

**Шаг 3. Подготовьте папку проекта.** Если проект лежит не в `~/tender_bot`,
подставьте свой путь во всех командах ниже.

```bash
cd ~/tender_bot
npm install
cp -n .env.example .env.local
```

**Шаг 4. Впишите адрес бота и секрет сбора.** Эти две команды придумывают новый
секрет, дописывают его вместе с адресом в настройки на компьютере, отправляют тот
же секрет на сервер и выкладывают бота заново:

```bash
cd ~/tender_bot
SECRET=$(openssl rand -hex 32)
printf '\nBOT_URL=https://tenderbot-blond.vercel.app\nINGEST_SECRET=%s\n' "$SECRET" >> .env.local
printf '%s' "$SECRET" | npx vercel env add INGEST_SECRET production
npx vercel --prod
```

Свой адрес подставьте вместо `https://tenderbot-blond.vercel.app`.

Строку `CRON_SECRET` в `.env.local` трогать не нужно — она там уже есть и остаётся
как была. `INGEST_SECRET` — отдельный секрет, который умеет ровно одно: принести
боту страницу. Это нарочно: `CRON_SECRET` заодно подписывает webhook Telegram и
открывает `/api/setup`, и такому ключу на домашнем компьютере не место.

Если `INGEST_SECRET` на сервере уже заводили раньше, `vercel env add` откажется
добавлять его второй раз. Тогда сначала уберите старое значение и повторите шаг:

```bash
cd ~/tender_bot && npx vercel env rm INGEST_SECRET production
```

Проверять правильность секрета руками не нужно — это делает шаг 5: если значения
на компьютере и на сервере разойдутся, скрипт скажет об этом словами и сбор
включать не станет.

Если отдельный секрет заводить не хочется, шаг 4 сводится к одной строке — тогда
сборщик возьмёт `CRON_SECRET`, который в файле уже лежит:

```bash
cd ~/tender_bot && printf '\nBOT_URL=https://tenderbot-blond.vercel.app\n' >> .env.local
```

Честно про этот вариант: `CRON_SECRET` — это ключ от всего бота сразу. Им
подписан webhook Telegram, им же открываются `/api/setup` и `/api/probe`, и тот,
кто его узнает, может делать с ботом что угодно. Копировать его на домашний
компьютер можно, но это осознанный размен: одна строка вместо четырёх — в обмен
на то, что ключ от всего лежит на ноутбуке, который ездит с вами. `INGEST_SECRET`
из полного шага 4 умеет ровно одно — принести боту страницу.

Заглянуть в файл глазами (он скрытый, в Finder его не видно):

```bash
open -e ~/tender_bot/.env.local
```

**Шаг 5. Включите сбор.**

```bash
bash ~/tender_bot/scripts/install-collector.sh
```

Скрипт сначала сам проверит связь с ботом и секрет и только потом скажет
«Готово». Если что-то не сошлось — он прямо скажет, что именно, и сбор включать
не станет. После «Готово» он тут же сделает пробный сбор и покажет его результат.

Всё. Дальше компьютер делает это сам каждые 15 минут, пока он включён и в сети.

### Как проверить, что работает

Запустите сбор вручную и посмотрите на ответ:

```bash
cd ~/tender_bot && npm run collect
```

Первый сбор выглядит так — и «разослано 0» здесь правильно:

```
Сборщик тендеров. Запуск 20.08.2026, 15:03:11
Спрашиваю бота (https://tenderbot-blond.vercel.app/api/ingest), какие площадки скачать...
Заданий: 1

[1/1] Все тендеры Кыргызстана (procurement.kg)
  качаю https://procurement.kg/
  скачано 152 КБ, отправлено боту
  бот разобрал: найдено 32, новых 32, разослано 0
  это был первый сбор: всё найденное помечено просмотренным,
  дальше в Telegram придут только новые тендеры

Итог: обработано 1 из 1.
```

Все следующие сборы выглядят так:

```
[1/1] Все тендеры Кыргызстана (procurement.kg)
  качаю https://procurement.kg/
  скачано 152 КБ, отправлено боту
  бот разобрал: найдено 32, новых 4, разослано 4

Итог: обработано 1 из 1.
```

Числа у вас будут свои: они зависят от того, сколько тендеров сейчас на площадке
и сколько из них подошло под ваши ключевые слова.

А вот такой ответ означает, что пропущен шаг 1 — площадка в боте не добавлена:

```
Заданий не было — бот не просил ничего скачивать.
```

Лечится в Telegram: бот → `/menu` → **🌐 Сайты** → **⭐ Готовые площадки** →
**«Все тендеры Кыргызстана (procurement.kg)»** → **➕ Добавить**. Переустанавливать
ничего не нужно, следующий сбор подхватит площадку сам.

Проверить, что сбор идёт и без вас:

```bash
launchctl list | grep collector
```

Если в ответ вывелась строка со словом `collector` — всё на месте.

### Как посмотреть, что происходило

```bash
tail -n 40 ~/Library/Logs/tender-collector.log
```

Только сообщения о неудачах:

```bash
tail -n 40 ~/Library/Logs/tender-collector.err.log
```

### Если сайт показал проверку браузера

В логе это выглядит так:

```
  не получилось: сайт показал страницу проверки браузера («Just a moment…»)
  что сделать: откройте https://procurement.kg/ в браузере на этом компьютере,
  дождитесь загрузки списка и запустите сборщик снова
  причину записал в карточку площадки в боте
```

Сделайте ровно это: откройте адрес в браузере, дождитесь, пока появится список,
и выполните `npm run collect`. Сборщик никакие проверки не обходит — он лишь скачивает
страницу так же, как браузер, и честно говорит, когда страницу не отдали.
Причина при этом уходит в бота: в карточке площадки видно, что сбор не удался и почему.

### Если тендеры перестали приходить

Сбор молчит по трём причинам: компьютер был выключен, папку проекта переименовали
или переносили, обновился Node.js. Во всех трёх случаях в карточке площадки в боте
появится предупреждение вида «последний раз страницу присылали 2 дня назад».

Посмотреть, когда сбор работал в последний раз:

```bash
tail -n 20 ~/Library/Logs/tender-collector.log
```

Проверить, что задание вообще зарегистрировано в системе:

```bash
launchctl list | grep collector
```

Если строки нет — или если папку проекта переименовали, перенесли, а также после
обновления Node.js — просто поставьте сбор заново. Пути к программам записаны
внутрь настройки, и после переезда они перестают существовать:

```bash
bash ~/tender_bot/scripts/install-collector.sh
```

Скрипт всё перезапишет и сам скажет, что теперь не так.

### Как отключить

```bash
bash ~/tender_bot/scripts/uninstall-collector.sh
```

Логи и сам проект останутся на месте, автоматический сбор просто прекратится.
Включить обратно — командой `bash ~/tender_bot/scripts/install-collector.sh`.

### Если площадка вдруг перестала пускать бота

Площадки меняются: та, что раньше открывалась серверу, может начать показывать
проверку браузера — и наоборот. Переключить способ обхода можно прямо в боте:
карточка площадки → кнопка **💻 Читать с моего компьютера**
(или **🌍 Читать без моего компьютера**, чтобы вернуть обычную проверку).
Удалять и добавлять площадку заново не нужно.

## Ключевые слова

| Запись | Что ловит |
|---|---|
| `ремонт` | слово «ремонт» целиком |
| `ремонт*` | «ремонта», «ремонтные», «ремонту» |
| `поставка мебели` | фразу целиком, слово в слово |
| `-аварийный` | минус-слово: отменяет совпадение, даже если сработало другое |

Поиск нечувствителен к регистру, «ё»/«е» и пунктуации. Пустой список ключевых слов
означает «присылать все новые тендеры».

## Ограничения

**Сайты, где список рисуется JavaScript'ом, не парсятся.** Бот скачивает HTML и
разбирает его — если площадка (например, `zakupki.gov.kg` на PrimeFaces) подгружает
таблицу отдельным ajax-запросом, в HTML её нет. Бот это распознаёт и говорит прямо.
Обходные пути:

- указать вместо страницы адрес её JSON/XML-выгрузки, если он у площадки есть;
- использовать «печатную» или облегчённую версию списка;
- для таких площадок нужен headless-браузер (Playwright) — в serverless это
  отдельная история с размером бандла, в текущую версию не входит.

## Архитектура

```
src/
  app/
    api/telegram/route.ts   webhook Telegram (grammY)
    api/cron/route.ts       плановый обход сайтов
    api/setup/route.ts      миграции + подписка на webhook
    api/ingest/route.ts     приём страниц от домашнего сборщика
    page.tsx                служебная страница статуса
  lib/
    db.ts        подключение к Neon + схема
    repo.ts      весь SQL: сайты, слова, админы, дедупликация, состояния
    scrape.ts    загрузка страницы, извлечение по селекторам, автоподбор
    match.ts     нормализация текста и матчинг ключевых слов
    checker.ts   обход сайтов и рассылка (общая середина у сервера и сборщика)
    ingest.ts    разбор и проверки тела запроса от домашнего сборщика
    notify.ts    форматирование сообщений
    bot/         меню, диалоги, обработчики
scripts/
  dev-bot.ts                локальный запуск через long polling
  collector.ts              домашний сборщик: качает страницы и отдаёт их боту
  install-collector.sh      включает сбор каждые 15 минут на этом компьютере
  uninstall-collector.sh    выключает его
tests/                      unit-тесты матчинга, парсинга и сборщика
```

Состояние диалога хранится в таблице `user_state`, а не в памяти процесса:
у serverless-функций нет общей памяти между запросами.
